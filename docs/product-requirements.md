# Voya Portal 产品需求基线

## 1. 文档信息

- 文档版本：`0.1`
- 更新日期：`2026-08-21`
- 当前阶段：需求梳理
- 需求状态标记：
  - **已确认**：用户已经明确提出，可作为后续方案依据。
  - **衍生约束**：为保证已确认需求安全、完整、可验收而必须满足的约束。
  - **待确认**：当前信息不足，禁止在未确认前固化为产品事实。

## 2. 本轮范围

本轮只定义产品能力、业务对象、权限边界、业务规则、查询条件和验收口径，不进入以下工作：

- 页面信息架构、菜单层级与导航设计；
- 页面布局、组件选择、视觉样式与交互细节；
- 原型、线框图、高保真设计或前端实现；
- 未经确认的业务状态、字段枚举和流程扩展。

## 3. 核心术语与主体边界

### 3.1 后台账户（Portal Account）

Voya Explore 内部或合作方使用 Voya Portal 的管理账户。后台账户通过登录页进入管理系统，并受部门、角色和权限控制。

### 3.2 当前账户（Current Account）

当前已登录 Voya Portal 的后台账户。当前账户可以修改自己的密码并退出登录。

### 3.3 管理员（Administrator）

具备相应系统管理权限的后台账户。管理员可以管理其他后台账户，并可修改其他后台账户的信息和密码。

> “管理员修改密码”在本需求中只指后台账户，不指 Voya C 端用户。管理员不得查看任何账户的原密码，只能执行安全的密码重置或设置新密码。

### 3.4 Voya 用户（Voya User）

Voya 的 C 端用户。用户可能通过 Voya App、外部 API 或其他业务渠道在系统中创建，但在 Voya 体系内应归并为唯一用户身份。

Voya 用户与后台账户是两类独立主体：

- 后台账户用于登录和操作 Voya Portal；
- Voya 用户是用户中心管理的业务对象；
- 两者的身份、权限、密码、状态和数据模型不得混用。

### 3.5 部门（Department）

用于表达后台账户的组织归属，并参与后台账户管理和权限管理。

### 3.6 角色（Role）

一组可复用的权限集合，可分配给后台账户。

### 3.7 权限（Permission）

控制后台账户能否查看特定业务资源以及能否执行特定业务操作的授权规则。

### 3.8 用户标签（User Tag）

用于对 Voya 用户进行业务分类的可维护标记。一个标签可关联多个用户，一个用户是否允许关联多个标签待确认。

### 3.9 用车订单（Vehicle Order）

订单中心管理的一类订单。当前已确认需求只覆盖用车订单的查询与筛选，订单详情字段、状态流转和业务操作待后续确认。

## 4. 产品能力范围

当前已确认四个能力域：

1. 身份认证与当前账户安全；
2. 系统设置；
3. 用户中心；
4. 订单中心。

该划分仅表示产品能力归属，不代表最终菜单、路由或页面结构。

## 5. 身份认证与当前账户安全

### AUTH-001 账号密码登录

**状态：已确认**

- Voya Portal 提供独立登录入口。
- 后台账户可以使用“账户 + 密码”登录。
- 登录成功后建立后台会话，并根据账户的部门、角色和权限提供授权能力。
- 登录失败时不得泄露账户是否存在等可被恶意利用的信息。

### AUTH-002 手机号验证码登录

**状态：已确认**

- 后台账户可以使用“手机号 + 短信验证码”登录。
- 手机号必须能够唯一定位可登录的后台账户。
- 手机号由国家/地区区号和本地号码共同构成，具体存储和展示格式待确认。

### AUTH-003 验证码安全规则

**状态：衍生约束**

- 验证码必须有有效期、发送频率限制、错误次数限制和重复发送限制。
- 验证码验证成功或超过有效期后必须失效。
- 不得在前端代码、日志或错误信息中暴露验证码。
- 短信服务商、有效期、发送间隔和每日上限待确认。

### AUTH-004 当前账户修改自己的密码

**状态：已确认**

- 当前已登录账户可以修改自己的登录密码。
- 修改密码前的身份校验方式待确认，候选方式包括验证原密码或短信验证码。
- 密码修改成功后是否终止其他设备会话待确认。

### AUTH-005 退出登录

**状态：已确认**

- 当前账户可以主动退出登录。
- 退出后当前会话必须失效，受保护资源不可继续访问。
- 退出后返回位置待后续交互阶段确定。

### AUTH-006 会话与登录保护

**状态：衍生约束**

- 未登录账户不得访问受保护的 Portal 能力。
- 会话过期后必须重新认证。
- 登录接口应具备防暴力破解、频率限制和必要的安全审计能力。
- 连续失败锁定策略、会话时长、多设备会话策略和“保持登录”能力待确认。

## 6. 系统设置

系统设置包含部门管理、角色与权限管理、后台账户管理。当前账户修改自己的密码和退出登录属于账户安全能力，但可以从系统设置或账户入口访问，最终入口不在本轮确定。

### 6.1 部门管理

#### SYS-DEPT-001 查看部门

**状态：已确认**

- 具备部门查看权限的后台账户可以查看已有部门及其基础信息。
- 部门基础字段至少需要部门唯一标识和部门名称；其他字段待确认。

#### SYS-DEPT-002 创建部门

**状态：已确认**

- 具备部门操作权限的后台账户可以创建部门。
- 部门名称是否要求全局唯一、同级唯一或允许重复待确认。

#### SYS-DEPT-003 修改部门

**状态：已确认**

- 具备部门操作权限的后台账户可以修改部门信息。
- 修改部门不得导致已有账户失去可解释的组织归属。

#### SYS-DEPT-004 删除部门

**状态：已确认**

- 具备部门操作权限的后台账户可以删除部门。
- 部门仍关联后台账户、子部门或权限范围时的删除规则待确认。
- 是否采用逻辑删除、停用或物理删除待确认。

#### SYS-DEPT-005 部门结构

**状态：待确认**

- 部门是平级结构还是树形层级结构；
- 一个后台账户属于一个部门还是多个部门；
- 是否需要部门负责人、部门编码、排序和启停状态；
- 部门是否同时承担数据权限范围。

### 6.2 角色与权限管理

#### SYS-ROLE-001 查看角色

**状态：已确认**

- 具备角色查看权限的后台账户可以查看已有角色及其权限配置。
- 角色基础字段至少需要角色唯一标识和角色名称；其他字段待确认。

#### SYS-ROLE-002 创建角色

**状态：已确认**

- 具备角色操作权限的后台账户可以创建角色。
- 创建角色时可以为角色配置权限。

#### SYS-ROLE-003 修改角色

**状态：已确认**

- 具备角色操作权限的后台账户可以修改角色基础信息和权限配置。
- 权限变更何时对已登录账户生效待确认。

#### SYS-ROLE-004 删除角色

**状态：已确认**

- 具备角色操作权限的后台账户可以删除角色。
- 已分配给后台账户的角色是否允许删除，以及删除前的账户迁移规则待确认。
- 系统内置角色是否允许修改或删除待确认。

#### SYS-ROLE-005 查看权限

**状态：已确认**

查看权限用于控制后台账户能否查看某一业务资源，至少包括：

- 是否可以访问某一业务能力；
- 是否可以查看该业务能力中的信息。

查看权限是否进一步区分列表、详情、字段或数据范围待确认。

#### SYS-ROLE-006 操作权限

**状态：已确认**

操作权限用于控制后台账户能否对业务资源执行动作。动作应按业务能力独立授权，不能用一个笼统的“可操作”覆盖全部高风险动作。

当前能够明确的操作权限包括：

- 部门：创建、修改、删除；
- 角色：创建、修改、删除、配置权限；
- 后台账户：修改账户信息、修改或重置密码；
- 用户标签：创建、修改、删除、为用户关联或解除标签；
- 其他业务操作随业务需求继续补充。

导入、导出、审核、停用等操作未在本轮确认，不得默认开放。

#### SYS-ROLE-007 权限执行一致性

**状态：衍生约束**

- 无查看权限时，不应获得对应业务数据。
- 有查看权限但无操作权限时，只能读取，不得执行未授权动作。
- 前端是否展示入口与后端是否允许请求必须保持一致，但前端隐藏不能代替服务端鉴权。
- 权限拒绝必须有统一、可审计的结果。

#### SYS-ROLE-008 角色分配关系

**状态：待确认**

- 一个后台账户只能拥有一个角色，还是可以拥有多个角色；
- 多角色权限是取并集、交集还是存在优先级；
- 角色是否限定在特定部门；
- 是否存在不受普通角色限制的超级管理员；
- 是否需要按部门或其他条件控制数据范围。

### 6.3 后台账户管理

#### SYS-ACCOUNT-001 查看后台账户

**状态：衍生约束**

- 为支持管理员修改其他账户，具备账户查看权限的管理员需要能够查找并识别后台账户。
- 后台账户与 Voya C 端用户必须使用独立的数据与权限体系。

#### SYS-ACCOUNT-002 修改其他后台账户

**状态：已确认**

- 具备账户操作权限的管理员可以修改其他所有后台账户的信息。
- 可修改字段范围待确认，至少涉及部门、角色和登录身份相关信息的可能性。
- 普通管理员是否可以修改同级或更高权限管理员待确认。
- 账户不能通过修改操作获得超出操作者授权范围的权限。

#### SYS-ACCOUNT-003 管理员修改其他账户密码

**状态：已确认**

- 具备密码管理权限的管理员可以为其他后台账户修改或重置密码。
- 管理员不得读取、找回或展示原密码。
- 修改密码必须记录操作者、目标账户、时间和结果，但不得记录明文密码。
- 是由管理员直接设置新密码、生成临时密码，还是发送重置链接待确认。
- 重置后是否强制目标账户下次登录修改密码、是否终止已有会话待确认。

#### SYS-ACCOUNT-004 后台账户生命周期

**状态：待确认**

- 是否允许创建、删除、停用、启用后台账户；
- 后台账户状态及状态转换规则；
- 账户名称、手机号和邮箱的唯一性规则；
- 账户是否必须同时绑定部门和角色；
- 离职或禁用后的数据保留和会话处理规则。

## 7. 用户中心

用户中心管理 Voya C 端用户的唯一身份，不管理 Portal 后台账户。

### USER-001 唯一用户身份

**状态：已确认**

- 来自 Voya App、外部 API 或其他创建渠道的用户，应在 Voya 体系内形成唯一用户身份。
- 每个 Voya 用户必须具有稳定、不可重复的内部用户唯一标识。
- 多渠道身份如何识别为同一用户、重复用户如何合并以及冲突如何处理待确认。

### USER-002 用户列表

**状态：已确认**

- 具备用户查看权限的后台账户可以查询 Voya 用户。
- 用户列表支持根据用户状态进行查询。
- 用户状态枚举、状态含义和状态转换规则待确认。
- 是否支持按用户 ID、手机号、邮箱、注册来源、标签等其他条件查询待确认。

### USER-003 用户详情

**状态：已确认**

用户详情需要展示以下信息：

- 用户唯一标识；
- 注册来源；
- 注册时间；
- 国籍；
- 电话号码；
- 电话国家/地区区号；
- 社交媒体账号；
- 出生日期；
- 邮箱地址。

字段规则：

- 注册来源应使用可维护的渠道定义，不得只保存不可解释的自由文本；具体渠道枚举待确认。
- 电话号码与国家/地区区号应结构化保存，并保留标准化号码用于唯一性判断或查询。
- 社交媒体联系方式应至少区分平台类型与账号标识；支持的平台类型及是否允许同平台多个账号待确认。
- 国籍编码标准、出生日期精度、邮箱验证状态和联系方式验证状态待确认。

### USER-004 用户隐私与敏感数据

**状态：衍生约束**

- 手机号、邮箱、出生日期和社交账号属于个人信息，查看和操作必须受权限控制。
- 是否对不同角色进行字段脱敏、是否允许导出、日志如何处理个人信息待确认。
- 所有用户数据访问和变更必须符合 Voya 适用的隐私、数据保留与跨境规则；具体法律适用范围待确认。

### USER-005 用户信息修改

**状态：待确认**

- 本轮只明确用户详情需要展示信息，尚未确认后台是否允许修改 C 端用户资料。
- 若允许修改，需要进一步确认可修改字段、验证流程、来源覆盖规则和审计要求。

## 8. 用户标签管理

### TAG-001 查看标签

**状态：已确认**

- 具备标签查看权限的后台账户可以查看已创建的用户标签。
- 标签至少需要唯一标识和标签名称；其他字段待确认。

### TAG-002 创建标签

**状态：已确认**

- 具备标签操作权限的后台账户可以创建用户标签。
- 标签名称唯一性、长度、字符和命名规则待确认。

### TAG-003 修改标签

**状态：已确认**

- 具备标签操作权限的后台账户可以修改标签。
- 修改标签名称不应破坏标签与现有用户的关联。

### TAG-004 删除标签

**状态：已确认**

- 具备标签操作权限的后台账户可以删除标签。
- 已关联用户的标签是禁止删除、二次确认后解除关联，还是归档停用待确认。

### TAG-005 用户分类

**状态：已确认**

- 具备标签操作权限的后台账户可以使用标签对用户进行分类。
- 系统需要维护用户与标签之间的关联和解除关系。

### TAG-006 标签规则

**状态：待确认**

- 一个用户是否允许关联多个标签；
- 是否支持批量关联或解除标签；
- 是否支持自动标签、标签分组、标签层级、颜色或有效期；
- 是否需要按标签查询用户；
- 删除或停用标签后的历史记录保留方式。

## 9. 订单中心

### ORDER-001 订单中心

**状态：已确认**

- 系统具有独立的订单中心能力域。
- 订单中心至少包含用车订单这一订单类型。
- 后续其他订单类型不得在未确认前推断。

### ORDER-VEHICLE-001 用车订单查询

**状态：已确认**

具备用车订单查看权限的后台账户可以查询用车订单，并支持以下筛选条件：

- 进单渠道；
- 采购渠道；
- 订单号；
- 客户联系电话；
- 客户名称；
- 采购单号；
- 下单时间。

### ORDER-VEHICLE-002 筛选字段规则

**状态：待确认**

- 进单渠道和采购渠道的业务定义、枚举来源及是否支持多选；
- 订单号和采购单号是精确匹配还是支持模糊匹配；
- 客户联系电话是否包含国家/地区区号，是否支持后四位查询；
- 客户名称的匹配方式；
- 下单时间使用的业务时区，以及按时间点还是时间范围查询；
- 多个筛选条件之间是否统一采用“同时满足”；
- 默认排序、分页规模及最大查询时间范围。

### ORDER-VEHICLE-003 用车订单结果与详情

**状态：待确认**

- 查询结果需要展示的字段；
- 用车订单详情需要展示的内容；
- 订单状态枚举与状态流转；
- 是否支持修改、取消、退款、备注、指派、导出等操作；
- 用车订单与 Voya 唯一用户身份的关联方式；
- 不同部门或角色可查看的订单数据范围。

| 用车订单 | 查看与查询 | 暂未确认 | 修改、取消、退款、导出等 |

## 11. 关键验收原则

### 11.1 权限验收

- 没有资源查看权限的后台账户不能获得对应业务数据。
- 只有查看权限、没有操作权限的账户不能完成写操作。
- 部门、角色、账户密码和标签的每类操作可以独立授权。
- 管理员修改其他账户时不能授予超出管理员自身授权范围的权限。
- 密码、验证码和敏感个人信息不得出现在明文日志或普通操作记录中。

### 11.2 身份边界验收

- 后台账户与 Voya C 端用户拥有不同的唯一标识、状态和权限体系。
- Portal 登录能力只面向被授权的后台账户。
- 用户中心展示的对象是 Voya C 端用户，不是 Portal 后台账户。
- 管理员修改“其他账户密码”不会修改 C 端用户凭证。

### 11.3 用户中心验收

- 不同来源创建的用户均可使用统一用户身份表达。
- 可以按已定义的用户状态查询用户。
- 用户详情能够表达注册来源、时间、国籍、电话及区号、社交账号、出生日期和邮箱。
- 标签能够被创建、修改、删除并用于用户分类。

### 11.4 订单查询验收

- 可以按七类已确认条件查询用车订单。
- 多条件查询结果符合最终确认的组合和匹配规则。
- 没有用车订单查看权限的账户不能获得订单数据。

## 13. 明确不做的推断

在获得进一步确认前，本文不默认以下能力存在：

- C 端用户登录 Voya Portal；
- 后台修改 C 端用户密码；
- 后台直接编辑 C 端用户资料；
- 用户数据或订单数据导入、导出；
- 订单取消、退款、审核或财务结算；
- 自动打标、用户画像或营销自动化；
- 多级部门、多角色、超级管理员或数据范围权限的具体规则；
- 除用车订单外的其他订单类型；
- 任何页面数量、页面结构、菜单形式或视觉实现。
